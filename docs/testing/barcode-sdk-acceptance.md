# 扫码（BarcodeReader SDK）部署与验收

上位机通过厂商的 **BarcodeReader 第三方 APP 触发与条码读取 SDK** 主动触发一轮解码，
把识别到的条码显示在“总览”页，逐行追加到管理员配置的结果文件，并可调用一个外发程序
把条码交给下游。本文是现场部署与验收步骤。

“总览”页上的 **扫码服务块**（2026-09-23 增加）集中了这三件事的配置与调试入口：
**采集条码**（不依赖 PLC 的手动触发）、**扫码库路径**、**外发程序路径**。

## 1. 部署前提

| 项 | 要求 |
| --- | --- |
| 扫码程序 | BarcodeReader 已安装、已授权、能进入主界面 |
| 项目模式 | 打开项目 → **触发 → 第三方 APP** → 点击**运行** |
| 相机/区域 | 项目里已配置相机与 RECT（识别区域），每个 RECT 对应一个条码位置 |
| SDK 位数 | `BarcodeReaderTrigger.dll` 必须是 **x64**，与 `hlm_app.exe` 一致 |

**部署时必须做的事**：把 SDK 的
`BarcodeReader_TriggerSDK_1.1.0_20260911_BarcodeRead\x64\BarcodeReaderTrigger.dll`
复制到 `hlm_app.exe` **同一个目录**。
上位机按名字加载该 DLL，Windows 会先搜索 exe 所在目录。

> **也可以不复制**：在“总览”页的扫码服务块里把 **扫码库路径** 填成该 DLL 的完整路径
> （例如 `D:\BarcodeReader_TriggerSDK_...\x64\BarcodeReaderTrigger.dll`）并保存。
> 留空 = 仍按上面的方式从程序目录按名字加载。路径在**下一轮扫码开始时**生效——
> 上位机只在两轮之间卸载旧库、加载新库，绝不会在一轮中途换。

> 该 DLL 是厂商文件，**不随本仓库分发**，也不打包进 CI 产物。
> 缺少它不会阻止上位机启动：PLC 控制、停止、急停全部照常，只有扫码功能报
> “扫码服务未启动，请先打开 BarcodeReader 并点击运行”。

## 2. 配置结果文件

1. 以**管理员**登录。
2. 进入“用户与设置” → “扫码结果追加文件路径”。
3. 填写结果文件的完整路径，例如 `E:\Test\Barcode.txt`（**父目录必须先存在**），
   点击“保存扫码路径”。
4. 页面显示“扫码结果追加文件路径已保存”才算成功；留空表示未配置。

文件格式与扫码程序自己写出的完全一致：**每条条码一行**，CRLF 结尾，
`^` 是条码内容自身的分隔符，例如：

```
C3003090^M10^260224^002695
C3003090^M10^260224^002696
```

上位机是**追加**写入：不覆盖、不删除历史行。一块板识别出 6 个码就是 6 行，
未识别到的位置**不写空行**，也不会用上一块板的旧码顶替。

> **不要**把这里配成扫码程序自己保存结果的那个文件（BarcodeReader 的保存规则里那个
> `Barcode.txt`）。那是扫码程序在写，上位机也在写，两个进程会交叉写同一个文件。
> 给上位机单独指定一个文件。

## 3. 一轮扫码是怎么跑起来的

1. **触发**：两种入口，都走同一轮逻辑。
   - PLC 侧扫码结束，置 **M15 = 1**（上升沿，且快照必须是新的）；
   - 或“总览”页扫码服务块的 **采集条码** 按钮（仅管理员，一轮进行中时禁用并显示原因）。
     台架调试就用这个——PLC 程序里 M15 还没有梯级，产线信号暂时指望不上。
2. 上位机提交一次触发（每次都是新的 requestId）。
3. 上位机每 50 ms 查询一次该 requestId 的结果，最长等 35 秒。
4. 结果到达后：显示在总览页 → 追加写入结果文件 → **调用外发程序**（若已配置）。

注意：SDK 是拿**当前所有已启用相机的最新缓存帧**去解码，**不是硬件触发拍照**。
所以 M15 必须在板子还在相机视野内时置位。

### 3.1 外发（把条码交给下游程序）

在扫码服务块里填 **外发程序路径** 并保存。留空 = 不调用。

本项目自带的 `需求/发送/TCP_HMI_V1.0.5.exe` 就是这样一个下游程序，**按它的命令行约定调用**：

- 每块板调用 **一次**，本轮解出的条码**每个一个参数**，按表格顺序传：
  `TCP_HMI_V1.0.5.exe C3003090^M10^260224^002695 C3003090^M10^260224^002696`
  未识别到的位置不参与（**一个空参数都不传**——该程序把空参数当格式错误整帧拒收）。
- 它自己会把这些参数拼成 `BARCODE<TAB>码1<TAB>码2…` 发给它连接的对端，
  接收侧按 TAB 拆行写文件。**所以「每个条码一个参数」是必须的**：把多个条码拼成一个
  参数，对端只会看到「一个含空格的条码」。
- 上位机**等它退出，超时 15 秒**（比该程序自己的连接+回复预算 15 秒留了余量）；退出码 0 才算成功，界面挂一行「（已外发）」。
- 失败（路径不存在 / 起不来 / 超时 / 退出码非 0）时：**条码照常显示、照常落盘**，
  另挂一行「（外发失败：…）」。
- **条码里含 TAB 或换行时本轮不外发**，提示「条码含制表符或换行，外发协议无法表示」。
  TAB 是该协议的字段分隔符、换行是帧结束符，送过去会串帧——宁可可见地不发。
  **条码里含空格没问题**（该协议不拿空格做分隔符）。
- 程序路径含空格没问题：上位机不经 shell，直接把程序路径和各参数分开交给系统。

**部署 TCP_HMI 的注意点**（从其反编译脚本核实）：

- 带命令行参数启动 = CLI 模式：发一帧、等对端回 `ExpectedReply`、写一行
  `Result.txt`、退出。**退出码 0 = 对端回了期望回复**；连不上/发送失败/回复不符
  都是非 0，并被上位机显示成「（外发失败：外发程序返回 N）」。N 的含义见它自己的
  `LOG.txt`。
- 不带参数启动 = GUI 模式：按它 ini 的 `Mode` 当 Server（监听）或 Client（连出去）。
  当前 ini 是 `Mode=Server` + `IP=192.168.2.47` + `Port=9000`，
  所以**同一台机器上让 GUI 窗口保持打开并点「连接」**，HMI 调 CLI 实例把条码发到它监听的端口。
- CLI 模式连接的是 ini 的 `IP`/`Port`，**不是** `Mode` 决定的那个方向，所以
  GUI 是不是真的在监听，要看它自己的 `LOG.txt` 里有没有「Server 端等待 Client 连接」。

## 4. 界面提示含义

| 显示 | 含义 |
| --- | --- |
| `条码/扫码：未配置（预留）` | 没配置结果文件路径，不会触发扫码 |
| `条码：已配置，等待扫码` | 已配置，还没扫第一块板 |
| `条码：扫码中…` | PLC 的 M11（相机触发中）为 1 |
| `条码：<一行或多行>` | 本轮识别到的条码，逐个列出 |
| `（另有 N 个位置未识别到条码）` | 有 N 个 RECT 本轮没读出码（空读保留空，不会用旧码填） |
| `（存储失败：…）` | 条码读到了，但没写进结果文件（目录不存在/无权限/被占用） |
| `条码：本轮未识别到条码` | 本轮完成，但一个码都没解出来 |
| `条码：上一轮扫码尚未结束，本次扫码结束信号未处理` | 上一轮还在等结果，这一块板的扫码结束信号被拒绝（不会排队） |
| `条码：读取失败 — 扫码服务未启动，请先打开 BarcodeReader 并点击运行` | BarcodeReader 没开，或没点运行，或 DLL 不在 exe 目录 |
| `条码：读取失败 — 扫码程序未处于「触发 → 第三方 APP」模式` | 项目模式不对 |
| `条码：读取失败 — 扫码程序未运行，请点击运行` / `…未打开项目` / `…未配置识别区域（RECT）` | 扫码程序那一侧还没准备好 |
| `条码：读取失败 — 扫码结果等待超时（35 秒）` | 35 秒内没等到结果（解码未取消，可再扫一次） |
| `条码：读取失败 — 扫码结果过大被截断，请按相机/识别区域筛选后重试` | 单次结果超过 SDK 的 128 KiB 上限，行被省略（**不是**"没读到码"） |
| `条码：读取失败 — 扫码服务已重启，本轮结果无法确认，请重新扫码` | 扫码程序中途重启，本轮结果不可信 |
| `（存储失败：结果文件写入不完整，请检查磁盘空间）` | 磁盘/配额中途写满，条码读到了但没完整落盘 |
| `（已外发）` | 外发程序已运行并以退出码 0 结束 |
| `（外发失败：外发程序不存在：<路径>）` | 外发程序路径填错或文件被移走 |
| `（外发失败：外发程序无法启动（…））` / `（外发失败：外发程序返回 <n>）` / `（外发失败：外发程序异常终止）` | 程序起不来 / 退出码非 0 / 被信号杀掉（对 TCP_HMI：非 0 表示连不上、发不出或对端回的不是期望回复，具体看它自己的 LOG.txt） |
| `（外发失败：外发超时（15 秒））` | 程序 15 秒内没退出，已被强制结束 |
| `（外发失败：条码含制表符或换行，外发协议无法表示，本轮未外发）` | 本轮有条码带 TAB/换行，送过去会串帧，**故意不发** |

扫码服务块自身的三行状态：

| 显示 | 含义 |
| --- | --- |
| `采集条码` 按钮禁用 + `需要管理员权限` | 未以管理员登录 |
| `采集条码` 按钮禁用 + `上一轮扫码尚未结束，请稍候` | 一轮还在进行中（按钮不可点，不是静默拒绝） |
| `扫码库路径已保存` / `外发程序路径已保存` | 路径保存成功（数据库已确认，非乐观提示） |
| `…保存失败：…` | 保存被拒（权限/换行符/数据库错误/另一项保存正在进行） |

## 5. 验收场景表

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 不配置路径，点“模拟拍照结束” | 显示“未配置”，不触发扫码（不调用 SDK） |
| 2 | 配置合法路径后保存 | 显示“扫码结果追加文件路径已保存”，总览页显示“等待扫码” |
| 3 | BarcodeReader 未运行，走一轮 | 显示“扫码服务未启动，请先打开 BarcodeReader 并点击运行” |
| 4 | BarcodeReader 运行但模式不对，走一轮 | 显示“未处于「触发 → 第三方 APP」模式” |
| 5 | 正常一块板，走一轮 | 总览页列出全部条码；结果文件新增对应行数 |
| 6 | 同一块板连续走两轮 | 文件追加 2 组；第二轮**不会**显示上一轮的码 |
| 7 | 某位置空读 | 显示“另有 N 个位置未识别到条码”；文件里不出现空行、不出现旧码 |
| 8 | 结果文件目录不存在 | 条码照常显示，并提示“存储失败：存储目录不存在” |
| 9 | 运行中重启 BarcodeReader | 不崩溃；下一轮的条码正常，重启那轮报“无法确认” |
| 10 | 扫码异常时按停止/急停 | 与扫码无关，停止与急停照常可用 |
| 11 | 一轮还没结束就让 PLC 再置一次 M15 | 显示“上一轮扫码尚未结束，本次扫码结束信号未处理”；第一轮的结果随后照常显示 |
| 12 | 把结果文件路径指向扫码程序自己写的那个文件 | 能跑，但**两个进程会交叉写同一个文件**——不要这么配 |
| 13 | **PLC 完全不置 M15**，点总览页“采集条码” | 正常跑完一轮：总览页列码、文件追加、外发程序被调用（这就是台架验收的主路径） |
| 14 | 未登录或操作员登录 | “采集条码”和两个保存按钮禁用，且旁边显示“需要管理员权限” |
| 15 | 配好外发程序，走一轮 | 程序被调用**一次**；每个条码是**一个独立参数**、按表格顺序；界面显示“（已外发）” |
| 16 | 外发程序路径填错 | 条码照常显示并落盘，另显示“外发失败：外发程序不存在” |
| 17 | 外发程序故意 `exit 3` | 同上，另显示“外发失败：外发程序返回 3” |
| 18 | 外发程序卡住不退出 | 约 15 秒后显示“外发超时（15 秒）”，被强制结束；条码不受影响 |
| 19 | 条码内容里带 TAB 或换行 | 界面上条码照常显示、文件照常写入，但**不调用**外发程序，另显示“条码含制表符或换行…本轮未外发” |
| 20 | 一轮没解出任何码 | 显示“本轮未识别到条码”，**不调用**外发程序 |
| 21 | 重启上位机 | 扫码库路径与外发程序路径都还在（不需要重填） |
| 22 | 改扫码库路径后不重启，直接扫下一轮 | 新库在下一轮开始时生效；若新库是另一个服务实例，那轮报“扫码服务已重启，本轮结果无法确认”（不冒充成功） |

## 6. 通过标准

- 场景 1–22 全部符合期望。
- 结果文件内容与扫码程序自己写出的格式逐字一致（逐行核对）。
- 外发程序收到的参数逐字等于本轮全部条码，每个条码一个参数、按表格顺序（用 TCP_HMI 时看它自己写出的 `barcode.barcode` 是否一行一个条码来核对）。
- 扫码服务不可用时，PLC 侧控制（停止、软件急停、复位、调宽）不受影响。
- 上位机日志与审计记录中**不出现完整条码值**。
